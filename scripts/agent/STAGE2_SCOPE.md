# Stage 2 requirement-to-evidence map

Authority: [incorporated issue #84](https://github.com/GiraffeTechnology/ArtFi/issues/84), especially sections 9–25, 32–39, and `docs/PRD.md` section 8. This is an implementation/evidence map, not a change to either governing record. It introduces no requirement, gate or new client approval cycle. The old mint-stage numbering in `docs/STAGE_2_ACCEPTANCE.md` is unrelated to this NO-HIL map.

## Current result and dependency facts

The application-side policy, durable workflow, recovery, transport and private browser integration have been extended beyond the original single BUY slice. Complete Stage 2 NO-HIL is **not delivered**.

The current independent Wallet source at commit `92fa67509ac8733644e1dd1e6766b83901367214` documents per-operation owner review/confirmation and explicitly lacks delegated session keys, autonomous broadcasting, standing signing permission and an HTTP agent-write endpoint (`README.md`, `docs/XIONGAN-WALLET.md`, `docs/testing/AGENT-PATH-TESTNET-REQUIREMENTS.md`). ArtFi's available operations machine contract is read-only health input (`operations-dependency.contract.json`). Neither interface can be treated as an autonomous executor.

Accordingly, `/agent` states this limitation and links to existing owner-confirmed ArtFi surfaces. The existing EIP-1193, native marketplace and official OpenSea review/sign paths remain available; a link to them is not presented as NO-HIL execution. No wallet confirmation boundary is weakened.

## Smallest factual remaining production code/interface work

1. Bind a concrete, approved bounded executor/smart-account/relayer contract that can enforce the user's signed authority independently of the operational process. The current Wallet's per-operation file inbox cannot do this. Its owner-confirmed path must stay owner-confirmed.
2. Implement the fixed adapter for that **actual** interface: supported actions, immutable request IDs, nonce/revocation/exposure semantics, submission acknowledgment, unknown-outcome discovery, canonical receipts and recovery. No user private key or raw signed transaction is to be stored in the web/API/runtime.
3. Bind the existing native/official-venue reviewed-plan reader and market observation sources to that authority model, preserving the exact Stage 1 validation and wallet/account/chain checks. Approval-only or unsupported plans remain unavailable.
4. Supply and independently verify the actual approved Oracle/source proof reader through the preserved boundary. No app-held role establishes RWA authenticity.
5. Run the missing original acceptance campaigns against those real interfaces. Configuration labels, secrets, a precompiled binary and synthetic adapter tests do not replace this work.

The reusable multi-action modules are parameterized by immutable mode and configured domain/chain. `BOUNDED_SIGNED_AUTHORITY` still has no executable external adapter in the delivered composition; only historical reads are possible. This is an explicit remaining implementation/interface boundary, not a claim that changing credentials alone completes Stage 2.
