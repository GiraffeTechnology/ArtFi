# Whole-receipt business comparison

This initial source slice validates the existing unsigned receipt plan and compares it with a frozen Wallet receipt policy and exact phase wire. It introduces no route, configuration, provider, journal write, capability, grant, signature request or execution permission.

`projectWholeReceiptBusiness` accepts the existing native plan shape. It validates the receipt EIP-712 segment against all ten sale fields, all eight correspondence fields and the chain/deployment domain. Registered plans require the existing version/proof-hash pair. It checks the existing grant-derived native operation ID using `kernelRequestDigest`, and returns both an explicit business projection and a detached, deeply frozen **complete native plan**. Transport IDs and the full principal remain in that plan for the existing postgrant checks; projection is never permission to strip them from the wire.

`matchWholeReceiptBusiness` compares the projected plan with the policy and exact nine-field phase wire obtained **inside the installation's authenticated held receipt context**. It validates canonical policy representations, phase ordering and nonce uniqueness, safe decimal nonce bounds, fee budgets, exact account/chain/deployment and calldata hash. It decodes and re-encodes the existing ABI. Funding binds all terms and a bounded nonempty signature. Registration binds the inner sale/correspondence, exact version and proof hash; payment binds the segment. Canonical re-encoding rejects appended ABI bytes and alternate encodings. Returned unsigned data omits calldata, signatures and raw proofs. Registration proof hashing matches data; it does not prove source authenticity or Kit admission.

Encoding references: existing ArtFi whole-receipt authorization/Kit source and the corresponding Wallet receipt-task/operation-encoding contract. Sale types reuse `saleIntentTypes`; the receipt authorization uses the existing `ArtFi Whole Artwork Receipt Settlement` version `1` domain. The regression source retains the inherited Solidity interoperability vector. This slice defines **no new pregrant digest or association algorithm**.

Integration remains open:

- Caller must authenticate the real stored grant, held snapshot, deadline, runtime code and peer; raw policy data has no authority. The helper does not recompute the Wallet task digest, verify revocation/TTL, reserve a phase/nonce, authenticate an Oracle record or prove chain canonicality.
- `phaseSlot.planDigest` and `journalBindingHash` are opaque retained policy values. This comparison does **not** verify those two commitments. Every successful result explicitly carries `authorization: "NOT_ESTABLISHED"`.
- The independent acceptance owner must integrate and validate the existing submitted typed consumer boundary. Its unsupported-receipt rejection must remain until exact business/association encoding, principal/full-plan/request digests, one-use capability/mTLS, single held action, durable CAS and recovery policy are wired end to end. This helper is not a replacement consumer and is not installed by this PR.
- Full native identifiers/principal and the original full plan digest remain mandatory after grant. A new grant can preserve business terms while changing native identity; it cannot inherit another operation's journal or renew an unknown send.
- Recovery must reconcile the existing immutable operation, retain wallet-start and unknown-result evidence, and recheck canonicality after a reorg. No automatic replay is introduced.

Authored regression source covers all phases, the fixed segment vector, detached data, grant/business separation, foreign sale/correspondence/domain/task/actor/phase, registration inner payload and proof, nonce/fee changes, ABI tails, descriptor/prototype/unknown-field refusal and the unresolved commitment boundary. Execution status must come from the independent Linux acceptance process. Source presence is not a test, installed integration or complete S-WA acceptance.
