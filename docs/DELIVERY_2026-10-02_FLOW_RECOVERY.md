# Existing holder, DAO and portfolio flow recovery

This bounded correction follows the current three-product delivery and the original application's wallet, transaction-status, holdings and history workflows. It preserves existing holder benefits and DAO contract policies; it does not adopt every historical PRD clause or introduce a new governance service.

Holder access is now bound to wallet, chain and edition. Late responses cannot verify a different context, expired grants hide the download, and descriptor errors remain retryable. Portfolio reads similarly retire the previous wallet's data immediately, ignore delayed cancelled responses and allow an explicit retry. Missing database configuration returns HTTP 503 for portfolio/NFT reads, while a connected empty account/catalogue still returns a successful empty result.

Existing DAO writes remain pending after broadcast and only report completion after a successful receipt. Revert, cancellation, replacement and unknown outcomes remain distinct. A tab-scoped shared record prevents a returning page from opening a second same-context wallet request; request generations and matching hashes prevent old callbacks from replacing newer recovery data. The last submitted proposal package and unresolved public transaction hashes survive reload. Restoring data never signs or executes an action, and wallet control must be verified again.

Two limits are explicit. Coordination covers one browser tab and wallet/chain/deployment context, not multiple tabs. If a hard reload destroys the wallet Promise before a transaction hash is known, the preserved marker remains unresolved and blocks new writes in that context; there is no supported safe unlock in this change. It does not guess a nonce, claim cancellation, clear storage to retry or present a checkbox as chain evidence. Known-hash uncertainty supports read-only receipt reconciliation.
