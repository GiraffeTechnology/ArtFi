### 1.4 ArtFi 是交易中介,不是交易所

客户裁定(2026-08-30):**ArtFi 是交易中介,不是交易所。** 这解掉 §4.1 原本待决的那一条,M2 即刻可开工。

确立的不变量:

> **ArtFi 永不占有、也永不持有移动用户资金或资产的权限。** 用户持仓的每一次变化,都源自该用户为那一笔交易本人签出的签名。ArtFi 记录意图、撮合对手方;链上完成清算。

对 M2 七组要求的影响 —— **六组原样保留,一组变性:**

| 要求                               | 处置                                                                                                                                                       |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 认证(SIWE / JWT / 会话 / 钱包绑定) | 保留                                                                                                                                                       |
| 订单系统                           | 保留,但订单是**签名意图**(EIP-712),不是托管订单;改单即替换签名意图,撤单即撤销                                                                              |
| 撮合引擎                           | 保留,价格-时间优先;输出是带双方签名的链上清算交易。**撮合是撮合,不是执行** —— 没有签名的匹配无法清算                                                       |
| 资金账本                           | **替换为持仓投影** —— 由链上事件只读投影,可与链上状态对账。复式记账约束投影自身的完整性,不构成对用户财产的权利主张。Redis 与 MySQL 都不是所有权权威,链才是 |
| 成交历史                           | 保留                                                                                                                                                       |
| 管理 API                           | 保留,但**任何管理动作不得移动、冻结或重新指派用户资产**。管理的是挂单、可见性与平台配置,不是财产                                                           |
| OpenAPI 3.1                        | 保留                                                                                                                                                       |

**清算托管方式(客户裁定,2026-08-30):签名清算。** 定价与订单簿路径走签名清算,资产始终留在所有者钱包,只在其本人签名的那一笔原子成交中移动;挂单时的 `_pullExact` 从该路径移除,合约不持有任何静置余额。

**托管仅保留给拍卖**,那里锁定是结构性必需:拍卖期间不锁标的物,卖方可以在看到中标价后把币转走,竞买人白锁资金一场。该锁定由卖方为发起拍卖主动接受,有 `startsAt` / `endsAt` 明确边界,并由不可暂停的 `settleAuction` 释放。

实现上必须成立的推论:定价路径不静置任何用户资产,因而没有可被攻破的资金池,暂停也困不住任何东西;卖方可以用同一批币在多处同时挂单 —— 挂单是授权,不是转移。

细节见 `PRD.md` §4.2.2,含一条已记录的缺陷:`cancelListing` 带 `whenNotPaused`,是卖方从活跃挂单取回托管资产的唯一出口,暂停会锁死它。本裁定把该缺陷收窄到拍卖路径,**没有消除它** —— G3-A 必修。

本形态在各司法辖区是否触发牌照义务,是客户法务的问题,不是实现决策。

### 1.4.1 两个角色:自营与中介 —— 一套规则

客户裁定(2026-08-30):ArtCCH:ArtFi 分为两个角色。

| 角色     | 卖的是谁的资产    |
| -------- | ----------------- |
| **自营** | ArtCCH 自己的持仓 |
| **中介** | 第三方的持仓      |

**这是业务角色,不是技术特权。** ArtCCH 出售自有库存时,以市场参与者身份行事:它的钱包就是一个参与者钱包,适用与其他任何人完全相同的规则。**把 ArtCCH 的资产当作客户资产看待,只不过那个 account/钱包归 ArtCCH 所有。**

由此产生三条要求:

1. **没有特权路径。** 不设卖方白名单,不用角色限制谁可以挂单,也不存在任何能移动 ArtCCH 持仓的管理接口 —— 就像它不能移动客户持仓一样。`createListing` / `createOffering` 目前对任何地址开放,**在这个模型下是正确的,不是缺口**。
2. **撮合对卖方身份盲。** 价格-时间优先不以卖方是谁为输入。ArtCCH 自己的订单**不享有任何排序、延迟、可见性或费率优势**,可重放的订单日志就是证明这一点的东西。
3. **披露,而非特权。** 挂单须披露卖方是否为 ArtCCH。自营/中介的区分对用户和账务可见,但**永远不作为清算路径上的分支出现**。

第 2 条是这条裁定里最容易被忽略、也最容易出事的一条:同一主体既运营场所又在场所内交易,是利益冲突面。**用「撮合不读卖方身份」这一条把它关掉,比事后解释便宜得多。**

### 1.5 合约早冻结,审计晚执行

外部审计后置**不等于**合约可以持续变更。二者必须解耦:

- M1 剩余项收口后,**合约套件立即冻结**;
- 冻结后,G2 运行时证据在该 bytecode 上采集;
- 外部审计在 P5 对**同一份 bytecode**执行。

理由:`ACCEPTANCE.md` §3 排除「来自不同 commit、分支、链或合约的测试结果」。若审计后置且合约仍在变,一条高危发现将同时作废合约与整套 G2 证据。**冻结点必须早于 M2/M3 开工。**
