# Native signed orders and ordinary wallet sessions

This change completes a bounded part of the original buy/sell order and persistent wallet-login workflows (original supplied material P49/P53/P55–57/P64–66), within the client's current three-product definition. It preserves the existing whole-receipt and fractional SaleIntent contracts. It does not adopt every historical issue or agent-written requirement, add a matching engine, change an economic model, or introduce Stage 2 authority.

The user can connect and sign in, sign the existing sale terms, explicitly publish them, find and load a public order or its exact link, and restore its terms after refresh and Back/Forward. The existing chain checks determine current fillability. Payment approval and settlement remain separate wallet requests, and a transaction is completed only after a successful receipt. Login itself grants no sale or transfer authority. Publication requires the matching seller's HttpOnly session and original sale signature; there is no additional publication-purpose signing protocol.

MySQL stores immutable public order envelopes. Exact retries retain their original publication time; conflicting envelopes are refused. List and exact-order reads are public and scoped by chain, market and asset. Connected empty storage returns an empty result; missing or failed persistence returns an error. The verifier credential and seller session are independently required for the internal publication route. An order record is not evidence of settlement, custody, physical ownership, pickup, or registry rights.

The ordinary user session is separate from registrar, holder-benefit and unrelated market APIs. SQL-backed challenges are single-use and bound to wallet, chain, origin and expiry. Access JWTs last ten minutes; sessions and refresh cookies have an absolute thirty-day expiry. Refresh tokens are stored as hashes, rotated atomically, and replay revokes the durable session. Logout remains effective after restart. Server credentials and session tokens never enter browser JSON or browser storage; cookies are HttpOnly and SameSite Strict. EOA login and sale signatures can be verified locally; the existing configured Hoodi reader is used for contract-wallet verification.

Every new market wallet request revalidates the ordinary session and its original wallet, chain and terms. Logout or a changed context retires old continuations, including approval-to-fill transitions, while public receipt recovery remains available. Journals retain the original intent identity. Only repricing can replace a transaction hash; cancellation and a different replacement cannot masquerade as a fill. Compare-and-replace updates stop late reconciliation from overwriting a newer journal. Receipt checks also recheck their live view context after follow-up queries, so a delayed result cannot label newly selected terms as settled.

Wallet and session controls remain reachable on mobile. A failed logout offers an explicit retry even after disconnect. Expiry, focus and token-free cross-tab notifications recheck local session state. Reading a different current session does not revoke it. Limits remain explicit: market wallet locks cover one tab; browsers without Web Locks serialize cookie writes per tab. Web Locks do not prove session ownership, and an explicit logout or confirmed wallet change targets the origin's current shared cookies. This change does not claim a complete cross-tab transaction mutex.

## Existing deployment contract

Coding and tests precede handoff to artfi control. SIN hosts UI and chain execution; CTYun hosts backend/MySQL through the existing bridge and operations setup. Both order and auth adapters retain configured bridge path prefixes. Next uses `ARTFI_WEB_URL` and `ARTFI_USER_AUTH_API_URL` (falling back to `ARTFI_API_URL`); Go uses `ARTFI_WEB_ORIGIN`. `ARTFI_USER_AUTH_BRIDGE_TOKEN` and `ARTFI_USER_SESSION_SECRET` are empty server-side deployment placeholders, to be handled through the existing secret workflow. No production credential was created or configured here.

The UI proxy must preserve the configured public Host and effective port. Publication checks that Host and the exact browser Origin independently; forwarded headers do not establish authority. This supports framework-normalized internal request URLs without weakening the public-origin boundary. For the current CTYun/SIN deployment, TCP 443 and occupied ports are excluded. Preserve SSH, shared bridges and other-task listeners. Inspect current allocations and select a suitable free non-443 port under the client's existing deployment authority; missing a prior named allocation is not a new client approval gate. Actual ingress authorization and complete configured public URLs still apply.

No deployment, real asset, mainnet transaction or financial operation was performed. The existing freeze archive remains preserved. This order/session slice does not claim that all three product sections or later mint/vault recovery work are complete.
